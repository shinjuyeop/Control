# KEYA 설정 도구

PySide6/QML GUI와 CLI가 같은 Python 통신 코어를 사용합니다. 현재 지원 대상은 원본 V4.3의 **Not 170 Three generations, 8바이트 Setup 설정 모드**입니다.

## 실행

이 디렉터리에서 실행합니다.

```bash
./run_gui.sh
```

`uv`가 있으면 의존성을 캐시에 설치해 사용합니다. 최초 설치에는 네트워크가 필요하며, 설치 후 GUI는 로컬에서 작동합니다. `uv`를 사용하지 않을 때는 Python 환경에 `requirements-gui.txt`를 설치하세요. 실행 스크립트는 ROS 셸의 Qt 라이브러리 경로와 PySide6 번들의 충돌을 피하도록 구성되어 있습니다.

## 화면 사용법

1. RS-232 포트를 선택합니다. USB 어댑터 설명과 경로가 함께 표시되며, 경로를 직접 입력할 수도 있습니다. **포트 찾기**는 포트 목록을 다시 검색합니다.
2. 정상 기동을 확인한 뒤 **연결**을 누릅니다. `포트 여는 중 → 포트 열림·응답 대기 → 설정 응답 수신 중`으로 진행 상태를 표시합니다.
3. 왼쪽에서 설정 분류를 선택합니다. 조향 튜닝은 가감속·위치·속도·전류 제어로 묶었습니다. 오른쪽에는 선택한 파라미터의 설명, 단위, 참고 범위, 확인되지 않은 의미를 표시합니다. 열 제목·값·버튼의 보조 설명은 마우스를 올리면 나옵니다.
4. **편집값**을 입력하고 **RAM에 적용**합니다. 변경값을 전송한 뒤 장치 RAM을 다시 읽어 비교합니다. 주황색 RAM은 ROM과 다른 값이고, 주황색 편집란은 아직 적용하지 않은 값입니다.
5. 영구 저장하려면 **EEPROM에 저장…**에서 차이를 확인합니다. Burn은 표시된 차이를 포함한 전체 RAM을 저장합니다. 원본 EXE 기준으로 5초 기다린 뒤 ROM을 재조회합니다.
6. **연결 종료** 후 컨트롤러를 재부팅합니다. 다시 정상 기동을 기다려 연결하고 저장값이 유지되는지 확인합니다.

연결 중에는 약 1초 간격으로 설정 스트림을 다시 읽습니다. 새로고침과 자동 갱신은 로컬 편집값을 유지합니다. 편집 시작 이후 장치 RAM이 달라지면 오른쪽에 충돌을 표시하고, 이전 값을 기준으로 한 쓰기를 거절합니다.

설정 수신 제한 시간 10초 내에 필요한 항목을 받지 못하면 자동 갱신을 멈추고 `응답 확인 필요`를 표시합니다. 원본 EXE는 0–63 주소를 세 bank에서 받을 수 있는 64칸 배열로 처리하므로 전체 순회는 최대 192레코드입니다. 실제 장치에서 약 28레코드/초가 관측되어 한 순회에 약 6.9초가 필요했습니다. 마지막 수신값과 시각은 남기되 적용·저장은 비활성화됩니다. **새로고침**으로 응답을 확인하면 자동 갱신을 재개합니다. 포트가 열려 있다는 사실만으로 정상 통신이나 구동 가능 상태를 표시하지 않습니다. 이 설정 프로토콜만으로 모터 모델을 식별하지 않습니다.

타임아웃의 **오류 상세**에는 수신 바이트 수가 표시됩니다. `수신 바이트가 없습니다`이면 선택 포트, TX/RX 교차 연결, 공통 GND, RS-232 전압 레벨, 컨트롤러 정상 기동을 확인합니다. 바이트가 있는데 레코드를 해석하지 못했다면 마지막 32바이트가 표시되므로 8바이트 Setup 프로토콜과 통신 설정을 대조할 수 있습니다. FT232R이라는 USB 장치명만으로 TTL UART인지 RS-232 레벨 변환기를 포함한 완제품인지 판별할 수는 없습니다.

### 값과 파일

| 화면 | 의미 |
|---|---|
| 적용값 | 컨트롤러가 보고한 Param 값 |
| RAM | 장치에서 수신한 작업 메모리 값 |
| ROM | 장치에서 수신한 EEPROM 값 |
| 편집값 | PC에서 입력한 값. RAM 적용 전에는 전송되지 않음 |

**편집 취소**는 PC 입력만 취소합니다. **백업** 메뉴는 마지막 수신 RAM 또는 ROM을 Windows 호환 `.ky` 파일로 저장합니다. 같은 이름의 파일은 덮어쓰지 않습니다. **파일 불러오기**는 변경값을 편집란에 넣으며 RAM 적용이나 Burn을 실행하지 않습니다. 읽기 전용 TAG는 복원 대상에서 제외됩니다. 달라지는 값 중 고급 항목이 있을 때는 **고급 편집 허용**이 필요합니다.

## 원본 EXE와 기능 대조

제공된 `kyMotor Control UtilityV4.3.exe`의 메서드와 `Languages/english.xml`, 모터 매뉴얼을 대조했습니다. **원본 프로그램 전체가 구현된 것은 아닙니다.**

| 원본 기능 | 현재 구현 |
|---|---|
| 포트 선택, Setup 연결·종료 | 지원 |
| 0000–0032, 0041, 0063의 Param/RAM/ROM 조회 | 지원: 35개 항목. 실제 수신하지 않은 값은 미수신 표시 |
| 각 항목 RAM 쓰기 | TAG를 제외한 34개 항목 지원. 일반·고급 편집으로 구분하고 변경값을 묶어 적용 |
| Burn | 지원. 5초 대기 후 ROM 재조회 비교 |
| RAM `.ky` 저장 | 지원. ROM 백업도 선택 가능 |
| `.ky` 불러오기 | 지원하되 편집란으로 불러옴. 원본은 RAM 전송 후 Burn까지 자동 실행 |
| 170 3세대의 4바이트 Setup 프로토콜 선택 | 미구현 |
| 모터 활성화·비활성화 | 미구현 |
| 속도·토크·절대위치·상대위치 직접 명령 | 미구현. 운전 모드 파라미터 0020 설정과는 별개 |
| 전류·전압·온도·속도·위치·전기각·고장 운전 모니터 | 미구현. 설정값 자동 갱신과는 별개 |
| 단일/듀얼 모터, Servo 185/170/170 3세대 운전·검사 화면 | 미구현 |
| 제조사 영문·중문 전환 | 현재 GUI는 한국어. 대조용 원문 항목명은 상세 설명에 표시 |

대조한 주요 메서드는 `MainForm.send_param`, `buttonWriteDev_Click`, `buttonLoadFile_Click`, `buttonControl_Click`, `buttonPosition_Click`, `buttonDisableControl_Click`, `GetStatustimer_Tick`, `process_servo_status`, `process_double_status`입니다. `MotorBForm`에는 별도 모터의 설정 경로가 있습니다. `button0Write_Click`은 빈 함수입니다.

0033 조향 영점과 0034 CAN heartbeat 시간은 해당 모터 매뉴얼에 있지만 이 V4.3 Setup 등록 항목에는 없습니다. 현재 도구도 해당 주소에 쓰기를 제공하지 않습니다. Burn은 설정의 EEPROM 저장이며 실행 펌웨어 교체가 아닙니다.

## CLI

```bash
./run_cli.sh --port /dev/ttyUSB0 dump
./run_cli.sh --port /dev/ttyUSB0 get accel
./run_cli.sh --port /dev/ttyUSB0 set accel 5
./run_cli.sh --port /dev/ttyUSB0 export keya-rom.ky --bank ROM
./run_cli.sh inspect keya-rom.ky
./run_cli.sh --port /dev/ttyUSB0 load keya-rom.ky --advanced
./run_cli.sh --port /dev/ttyUSB0 burn --yes
```

CLI 옵션과 별칭은 기존 인터페이스를 유지합니다. `set`, `load`는 RAM만 변경합니다. 0000 TAG는 `--advanced`로도 쓸 수 없습니다.

## 하드웨어 조건과 검증 범위

TTL UART가 아닌 RS-232 레벨 변환 어댑터를 사용하세요. 제조사는 **전원 투입 순간 설정을 읽으면 초기값으로 리셋될 수 있다**고 경고합니다. 정상 기동 이후 설정 세션을 시작하고, 읽기만 했더라도 종료 후 컨트롤러를 재부팅해야 합니다. CAN 구동 중 RS-232 설정을 병행할 수 있다는 근거는 확보되지 않았습니다.

검증은 기존 프로토콜 테스트와 Qt 오프스크린 화면·입력, 가짜 전송 계층을 통한 worker 연결·적용·저장·응답 단절·복구 흐름으로 수행했습니다. 실제 RS-232 통신, 모터 동작, 전원 재투입 후 값 유지 여부는 아직 검증하지 않았습니다.

## 코드 구조

`keya/parameters.py`는 값의 인코딩, `parameter_help.py`는 한국어 설명, `protocol.py`는 바이트 형식과 `.ky`, `transport.py`는 pyserial과 수신 버퍼, `controller.py`는 읽기·적용·저장을 담당합니다. `keya_v43_gui.py`의 한 QThread가 시리얼을 소유하며, QML은 화면과 입력을 담당합니다.
