# 토크 모드 조향 제어 — 방법 A (피드포워드 + 피드백) 설계 문서

전제
- 판단팀에서 넘어오는 목표 조향각은 이미 어느 정도 다듬어진(궤적화된) 상태로 가정한다. 따라서 방법 B(자체 궤적 생성)는 하지 않는다.
- KEYA 드라이버를 Torque 모드(0020=2)로 두고, 바깥 위치 루프 + 피드포워드를 ROS에서 구현한다.
- 안쪽 전류(토크) 루프는 KEYA 펌웨어에 그대로 남긴다.

---

## 1. 제어 법칙 (매 프레임 계산)

매 20ms(50Hz)마다 아래를 새로 계산한다. 정적 각도→토크 매핑이 아니라, 그 순간의 상태에서 매번 재계산한다.

```
오차        e      = θ_target − θ_actual
각속도      ω      = (θ_actual − θ_actual_prev) / dt      (또는 motor_speed_rpm 환산)
목표각가속도 α_ff  = 판단팀 궤적의 2차 미분, 또는 목표속도 변화율에서 추정

토크_물리 = J·α_ff        (피드포워드: 관성 선제 보상)
          + Kp·e          (피드백 P: 위치 오차)
          − Kd·ω          (피드백 D: 감쇠)
          + F_c·sign(e)   (마찰/데드존 보상: breakaway 돌파)

토크_지령 = clamp( 스케일(토크_물리), ±TORQUE_LIMIT )   // -10000~+10000
send_torque(토크_지령)   // watchdog 유지 위해 매 프레임 무조건 송신
```

구성 항의 역할
- J·α_ff : 관성 피드포워드. 목표가 가속을 요구할 때 필요한 토크를 오차가 생기기 전에 미리 넣는다. 방법 A의 핵심.
- Kp·e : 위치 오차 비례. 목표에서 벗어난 만큼 되돌린다.
- Kd·ω : 감쇠. 오버슛/진동 억제. (현재 Position 모드에서 ζ=0.64를 만들던 그 감쇠 역할을 여기서 직접 담당)
- F_c·sign(e) : 정지 마찰 데드존 돌파. 이게 Position 모드에서 불가능했던, 토크 모드로 가는 진짜 이유.

## 2. 파라미터 3분류

### (A) 현재 mcap으로 획득/추정 가능한 것

| 파라미터 | 기호 | 획득 방법 | 현재 데이터 근거 |
|---|---|---|---|
| 등가 관성 (초기 추정) | J | 큰 각 step의 각가속도 α와 그때 전류(→토크)에서 J≈τ/α 역산 | amp12/15에서 α≈7~11 rad/s², 단 전류 1A 양자화로 거칠다 |
| 목표 감쇠비 | ζ_target | 현재 큰 각 응답에서 ζ=0.64가 양호 → 이 값을 목표로 삼음 | amp15/18에서 OS 7~8%, ζ≈0.64 |
| 데드존/마찰 토크 (초기값) | F_c | 기존 deadzone_measure 결과 ±106 count 상당 | 별도 측정 기록 존재 |
| 전류→토크 스케일 | — | 데이터시트: -10000~+10000 = ∓rated torque, 제한전류=(cmd‱)×정격전류×80% | 데이터시트 4.3.2 / 14.txt 확정 |
| 현재 오버슛-진폭 관계 | — | amp3~18 스윕에서 진폭별 OS% 곡선 이미 확보 | 작은 각일수록 OS 증가 확인됨 |

주의: J는 전류 양자화(1A) 때문에 현재 mcap에서는 크게만 잡힌다. 방향(자릿수)은 얻지만 정밀값은 아래 실험이 필요하다.

### (B) 새로 실험해서 획득해야 하는 것

| 파라미터 | 기호 | 실험 방법 | 왜 필요한가 |
|---|---|---|---|
| 정격 토크의 물리값 | τ_rated | 모터 사양서 확인 또는 알려진 부하로 토크 인가해 역산 | J·α_ff를 -10000~+10000 스케일로 물리 환산하려면 필수 |
| 등가 관성 (정밀) | J | 무부하에서 계단식 토크 인가 → 각가속도 측정 → J=τ/α. 전류 양자화 피해 지령 토크값 사용 | 피드포워드 계수. 정밀값 필요 |
| 마찰 토크 (정밀) | F_c, F_v | 토크를 서서히 올리며 움직이기 시작하는 지점(정지마찰), 등속 유지 토크(운동마찰) 측정 | 마찰 보상 항. 데드존 돌파의 핵심 |
| 바깥 루프 Kp | Kp | 토크 모드에서 실측 튜닝 (ROS param) | 50Hz 루프라 Position 모드값 재사용 불가, 새로 잡아야 |
| 바깥 루프 Kd | Kd | 토크 모드에서 실측 튜닝 (ROS param) | ζ_target=0.64 재현하도록 |
| 데드밴드 폭 | ε | 목표 근처 몇 도까지 마찰보상 끄고 허용할지 실측 | 목표에서 미세 떨림 방지 |
| 0028 과부하시간 적정값 | — | 데드존 돌파 시 순간 대전류가 보호에 안 걸리는지 실측 | 현재 1초로 짧아 돌파 중 차단 위험 |
| 0026 방향 부호 | — | 작은 +토크 인가 후 실제 회전 방향 확인 | 부호 반대면 발산. 최우선 검증 |

### (C) 새로 생기는 (튜닝) 파라미터 — ROS 측

이 값들은 펌웨어가 아니라 ROS 노드/yaml에 새로 생긴다. `ros2 param set`으로 실시간 튜닝.

- `Kp` : 바깥 위치 루프 비례 게인
- `Kd` : 바깥 위치 루프 미분 게인
- `J_ff` : 피드포워드 관성 계수 (물리 J와 스케일 합친 실효값으로 둬도 됨)
- `F_c` : 마찰 보상 토크 (지령 단위)
- `deadband_deg` : 목표 근처 마찰보상 off 구간
- `torque_limit` : 지령 상한 (±8000 = 정격 80%, 보호 회피)
- `friction_gain_schedule` : (선택) 오차 크기별 F_c 스케줄 계수 — 사용자 아이디어(오차→보상게인)를 여기 반영
- `max_torque_rate` : (선택) 지령 급변 제한

구현된 ROS 파라미터 이름(`/steering_actuator_node`, [Experiment_RUNBOOK](Experiment_RUNBOOK.md) 5.5절 T3 표):

| 설계 이름 | 구현 파라미터 | 비고 |
|---|---|---|
| `Kp` | `torque_peak_limit_raw` / `torque_full_scale_error_deg` | 기존 구조 유지: Kp = peak / full-scale-error |
| `Kd` | `torque_kd` | raw/(rad/s) |
| `J_ff` | `torque_inertia_ff` (+ `torque_feedforward_limit_raw`, `torque_feedforward_filter_hz`) | α_ff는 명령 timestamp 2차 차분 |
| `F_c` | `torque_friction_raw` | int raw |
| `deadband_deg` | `torque_friction_deadband_deg` | |
| `torque_limit` | `torque_peak_limit_raw`, `torque_sustained_limit_raw` | 시간 예산 포함 |
| (접지) F_c(v) | `torque_friction_schedule` | `[v_mps, raw, ...]` |
| `friction_gain_schedule`, `max_torque_rate` | 미구현 | 선택 항목 |

## 3. 구현 순서 (안전 우선)

바퀴를 띄운 상태에서 아래 순서로. 각 단계 통과 후 다음으로.

1. 0020=2 전환 + enable. 아주 작은 +토크(예: +500) 인가 → 실제 회전 방향 확인.
   - 기준: **왼쪽(LEFT)이 +**. +토크에서 바퀴가 왼쪽으로 돌고 count·바퀴각이 증가해야 한다.
   - 반대로 돌면 ROS `torque_direction_sign=-1`(0026은 0 유지). 이 검증 없이 다음 금지.
2. watchdog keep-alive 확인: 매 20ms send_torque, 목표 도달해 토크 0이어도 send_torque(0) 지속. 1초 내 미송신 시 보호 걸리는지 실측.
3. torque_limit(±8000) 클램프 넣고, F_c=0, J_ff=0 상태로 순수 PD만으로 큰 각(±15/18°) step 추종. Kp/Kd 튜닝해 ζ≈0.64 재현.
4. 마찰 보상 F_c 추가 → 작은 각(±3/5°) 정착 오차/오버슛 개선 확인. deadband ε 조정.
5. 피드포워드 J·α_ff 추가 → 빠른 궤적 추종 시 지연/오버슛 개선 확인.
6. (선택) 오차 크기별 F_c 스케줄 적용.
7. 무부하 완료 후 접지 상태 재검증.

## 4. 핵심 리스크

- 부호(0026) 오설정 시 즉시 발산. 1단계에서 반드시 차단.
- 전류 1A 양자화: 피드백 루프에 전류 쓰지 말 것. 피드백은 각도(motor_angle 0.036°/count)만.
- 80% 보호(5초): torque_limit로 원천 회피. 데드존 돌파 순간 대전류가 0028에 안 걸리는지 확인.
- 50Hz 루프 한계: 안쪽 전류 루프(kHz)는 드라이버에 남겨 대역폭 분리 유지. 바깥 루프만 ROS.
- J 정밀도: 피드포워드는 J가 부정확해도 피드백이 흡수하므로, 초기엔 거친 J로 시작해 점진 보정 가능.
