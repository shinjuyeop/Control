## 2. 최우선: 조향 저전압과 영점 확인

9월 19일 4 m/s Run은 **15:58:17.383에 KEYA `fault_bits=16(0x0010)` → 위치 피드백 단절 → CAN_LOST** 순서였다. 화면에 남은 12 V는 느린 조회/캐시 값이므로 순간 전압 강하를 배제하지 못한다.

- [ ] KEYA 전원/DC-DC, 릴레이, 커넥터, 접지를 확인한다.
- [ ] 가능하면 KEYA 전원 단자에서 조향 부하가 걸릴 때의 순간 전압을 측정한다.
- [ ] TUI의 **`조향 원인 · 조치 안내`**와 `/steering/status`의 `state`, `disable_reason`, `fault_bits`, `feedback_age_ms`를 함께 확인한다.
- [ ] fault가 재발하면 비트와 시각을 남긴다. 재시작만 반복해서 통과시키지 말고 전원 문제인지 의도적인 전원 차단인지 구분한다.
- [ ] 물리적인 직진 바퀴 위치와 엔코더 영점·링크 유격을 확인한다. 기존 데이터의 직진 후보에서 약 −1.17°가 나왔지만, 그 값을 그대로 offset 보정값으로 사용하지 않는다.

**다음 단계 조건:** 현재 fault·통신·피드백 문제가 해소되고, 조향 부하에서 재발하지 않는지 확인된 뒤 게인 비교로 넘어간다. 이 단계가 해결되지 않으면 고속 시험보다 원인 확인을 우선한다.

## 3. 종방향: 현재 EZ 설정을 확보한 뒤 Ki부터 비교

### 3.1 앱에서 먼저 기록할 항목

- [ ] EZkontrol firmware/version.
- [ ] `Rotor speed Kp`, `Rotor speed Ki`.
- [ ] `Acceleration`, `Deceleration`.
- [ ] `Phase current Kp/Ki`, `Bus current Kp/Ki`, 최대 상전류·버스전류.
- [ ] `EBS reference current`, `EBS auto mode enable`, `EBS max voltage`, `EBS min rotor speed`.
- [ ] 기록값을 Run 폴더에 사진 또는 메모로 남긴다. ROS의 `control_parameters.yaml`은 **EZ 내부 설정을 자동으로 읽지 않는다.**

기존 문서의 Kp=2/Ki=16, EBS 0 A·Disable은 **9월 8일 값**이다. 오늘도 같은 값이라고 전제하지 않는다. 설정 적용 시 EZ가 자동 재시작하므로 정지 상태에서 변경하고, 재연결·상태 수신과 적용값을 확인한다.

### 3.2 RPM과 실제 차속의 불일치 확인

- [ ] `/drive/status.motor_rpm`, `speed_mps`와 GNSS 속도를 같이 기록한다.
- [ ] 감속에서 RPM 환산속도만 급증/반전하는지 확인한다. 지난 기록의 12.46 m/s는 같은 시각 GNSS 약 6.14 m/s와 달랐다.
- [ ] RPM 이상이 반복되면 Hall 센서·배선·커넥터·원본 CAN을 대조한다. 이를 실제 차량 가속으로 단정하거나 PI만으로 가리지 않는다.
- [ ] `bus_current_a`, `phase_current_a`, `commanded_motor_rpm`, `commanded_phase_current_a`, brake/RUN을 함께 확인한다. AUTO의 480 A 명령은 **전류 한도**다.

### 3.3 러너 TUI 입력값

공통: **시험 조건=주행, MCAP 녹화=ON**.

| 화면 항목 | 설정 |

| 낮은 속도 | **3.0 km/h** |
| 높은 속도 | **5.0 km/h** |
| 편도 변화시간 | **5.0 sec** |
| 초기 유지시간 | **2.0 sec** |

이 시나리오는 조향을 Disable하므로, 별도 조향 운용을 준비하고 이 기록으로 횡방향 PD 성능을 평가하지 않는다.

### 3.4 EZ 내부 speed PI 비교표

**현재 readback이 실제 Kp=2/Ki=16이고 앱에서 아래 입력을 지원할 때의 후보**다. 다르면 현재값을 기준으로 Ki 약 10–20% 감소부터 비교한다.

| Run | Rotor speed Kp | Rotor speed Ki | 진행 기준 |
|---|---:|---:|---|
| L0 기준 | 2 | 16 | 원래 응답 기록 |
| L1 | 2 | **14** | Ki만 낮춰 undershoot·재상승·전류 반전 비교 |
| L2 선택 | 2 | **12** | **L1이 개선된 경우만** 추가 비교 |
| L0 재확인 | 2 | 16 | 노면·온도·SOC 변화와 게인 효과 구분 |

- [ ] L1에서 지연이 늘거나 진동/undershoot가 개선되지 않으면 원복한다.
- [ ] EBS, 전류루프 PI, 전류한도, 필터, 상위 ramp는 이 비교 중 고정한다.
- [ ] `Deceleration=100`의 단위·증감 방향·CAN 적용성이 불명확하므로 임의로 50이나 200으로 바꾸지 않는다.
- [ ] Kp=2→1은 50% 변화다. Ki와 동시에 변경하거나 작은 미세조정으로 취급하지 않는다.

**판정:** 새 목표 아래 최저속도, 재상승량, 정착시간, 감속거리, 전류 반전, RPM–GNSS 차이를 비교한다. 전류만 매끄러워지고 감속거리가 늘면 충분한 개선이 아니다. 저속 결과를 확보한 뒤 속도를 확대할지 결정한다.

## 4. 횡방향: 종방향 조건을 고정하고 P/D 비교

종방향 비교에서 사용할 설정을 먼저 정한 뒤 아래 시험 동안 유지한다. 조향 게인과 종방향 Ki/감속 방식을 동시에 바꾸지 않는다.

### 4.1 Control Tuning TUI 공통값

프리셋 **주행**을 선택한다. P/D는 Enter로 직접 입력하고, Run 사이에 **A → 검토 → Enter**로 적용한다. `현재 적용값`과 Run의 `control_parameters.yaml`을 확인한다. `S`는 다음 launch용 프리셋 저장이며, 선정 후 저장한다.

| 화면 항목 | 고정값 |
|---|---:|
| 목표 도달 오차 / 목표 도달 속도 | **0.1 deg / 0.5 deg/s** |
| 조향속도 필터 | **10 Hz** |
| 최대 전류 명령 / 지속 전류 명령 | **16 A / 8 A** |
| 고출력 허용 시간 / 재사용 대기시간 | **1000 ms / 5000 ms** |
| 조향 한계 보호 여유각 | **1 deg** |
| 조향 제어 방식 / 허용 최소 차속 | **torque / 0.5 km/h** |

센터각은 이전 시험과 비교하려면 **−1°로 통일**한다. 검증된 직진 영점이라는 뜻은 아니다. 물리 중심을 확인해 다른 값을 선택한다면 기준 Run부터 모두 같은 값으로 시험한다.

### 4.2 필수: 작은 Step에서 P와 D를 따로 변경

시나리오 **조향 양방향 Step**, 시험 조건 **주행**, 녹화 **ON**.

| Run | P 게인 | D 게인 | 주행속도 | 센터각 | 조향 진폭 | 구간 유지시간 | 초기 직진시간 | 반복 횟수 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A0 기준 | **2.4** | **0.08** | 5 km/h | −1° | 3° | 2 sec | 2 sec | 3 |
| A1 P 비교 | **2.0** | **0.08** | 5 km/h | −1° | 3° | 2 sec | 2 sec | 3 |
| A2 D 비교 | **2.0** | **0.06** | 5 km/h | −1° | 3° | 2 sec | 2 sec | 3 |
| A0 재확인 | **2.4** | **0.08** | 5 km/h | −1° | 3° | 2 sec | 2 sec | 3 |

각 Run 입력시간은 **26초**, 실제 목표각은 **−1→+2→−1→−4°**다. 첫 변화는 초기 직진과 첫 센터 유지 때문에 입력 시작 약 4초 뒤다. A1이 악화되면 A2를 자동 진행하지 않고 기준값으로 돌아간다.

### 4.3 후속: Sine로 지연과 진폭 손실 비교

시나리오 **조향 Sine · 고정 주기**. 공통값: **주행속도 5 km/h, 센터각 −1°, 조향 진폭 3°, 파형 주기 4 sec, 초기 직진시간 2 sec, 반복 6회**. 입력시간은 **26초**다.

| Run | P / D | 비교 목적 |
|---|---|---|
| B0 | 2.4 / 0.08 | 작은 입력의 기준 지연·진폭비 |
| B1 | 2.0 / 0.08 | P 감소에 따른 진동 개선과 추종 손실 |
| B2 선택 | 2.0 / 0.06 | Step에서 양호할 때만 D 감소 효과 확인 |

**판정 우선순위:** 유지 중 채터링·약 6 Hz 진동 감소 → overshoot → 작은 각도 지연·잔류오차 → 전류 반전·포화/peak 제한. 평균오차만 작고 계속 왕복하는 조합을 선정하지 않는다.

### 4.4 여유가 있고 앞 시험이 양호하면: 차속 의존성

선정된 **한 P/D를 고정**하고 위 Sine의 **주행속도만 3→5→7 km/h**로 바꿔 비교한다. 센터각·진폭·주기·초기 직진·반복 횟수는 그대로 둔다.

- [ ] 목표가 아니라 **실제 차속이 비슷한 구간**끼리 비교한다.
- [ ] 정속 준비 timeout 뒤에도 러너는 입력을 계속할 수 있으므로 경고 여부와 실제 차속을 기록한다.
- [ ] 이 데이터로 연속 차속 P/D의 필요성을 판단한다. 우선 시험 속도를 나누는 것이며 운용 게인을 계단식으로 바꾸는 것은 아니다.
- [ ] 연속 보간을 구현할 경우 제어기 내부에서 effective P/D를 계산해야 한다. 현재 `ros2 param set`을 매 주기 호출하면 Disable/reset이 반복되므로 사용하지 않는다.

## 5. 이번 현장 시험과 구분할 개발 항목

### 타력 감속 선택 모드

- [ ] 감속 판단을 확정한다: **실제속도가 목표 이상인 동안 계속 0 torque**인지, **목표속도 하강 구간만 0 torque**인지.
- [ ] 가속 재개 경계와 반복 전환 방지, feedback 이상·정지 요청 처리를 정한다.
- [ ] 러너 선택값이 실제 STM_A 출력까지 전달되고 기록·피드백으로 구분되도록 구현·검증한다.
- [ ] 메시지 계약을 바꾸는 설계라면 Host/STM_A/STM_B 호환 작업과 보드 반영도 별도로 수행한다.
- [ ] 완료 후에만 같은 Ramp로 기존 모드와 비교한다. **현재 TUI에 선택 항목이 없으므로 당장 실행할 시험 목록에 넣지 않는다.**

### 고속 경로·회생·연속 게인

- 6 m/s는 **21.6 km/h**다. 앞의 5~7 km/h 비교를 고속 검증으로 취급하지 않는다.
- 6 m/s 경로 재시험은 조향 저전압과 종방향 과속·감속 문제를 정리한 뒤 별도로 판단한다. 고속에서 큰 조향 Step부터 시작하지 않는다.
- EBS current 증가나 EBS auto Enable을 속도 PI 시험과 동시에 시행하지 않는다. 회생은 실제 firmware의 명령 계약과 팩/BMS 충전 허용량을 확인한 뒤 별도 시험한다.
- 연속 P/D 함수의 구체적인 속도별 끝값은 이번 고정 게인 시험 결과를 보고 정한다.

## 6. 기록과 종료 정리

- [ ] Run마다 **시험 조건=주행, MCAP 녹화=ON**을 확인한다. 시험 조건 선택은 기록용이며 P/D 적용 기능이 아니다.
- [ ] `control_parameters.yaml` 캡처 성공을 확인하고 EZ 내부 설정은 별도 메모한다.
- [ ] `/steering/status`, P/D 기여, 명령 전류, rate/raw rate, saturation, peak-limited, settled, torque_safety와 `/drive/status`, `/vehicle/command`, GNSS 속도가 실제 기록됐는지 확인한다. 토픽 목록에 있다는 것과 메시지가 수신됐다는 것은 다르다.
- [ ] fault가 발생하면 당시 원본 비트·상태·피드백 age·전압 측정·시각을 보존한다.
- [ ] `S`로 시험을 정리한 뒤 저장 완료를 확인한다. 새 설정·다음 Run 전에 MANUAL·정지 상태를 확인한다.
- [ ] 선정한 설정과 원복할 설정을 구분해 저장한다. 시험 때 띄운 프로세스와 저장된 파일을 정리한다.

Run별 메모는 아래 정도면 충분하다.

| Run 폴더 | EZ speed Kp/Ki | 조향 P/D | 실제 차속 범위 | 진동/overshoot·undershoot | fault·RPM 이상 | 유지/원복 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

**시간이 부족하면:** 전원·설정 readback과 L0/L1, A0/A1 및 결과 기록을 우선한다. 한 번에 모든 게인을 바꾸는 것보다 같은 조건의 유효한 비교 한 쌍을 확보하는 것이 우선이다.
